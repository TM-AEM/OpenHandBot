# OpenHandBot

بوت تيليجرام للتحكم في شاتات OpenHands Cloud من موبايلك بسرعة، من غير ما تفتح الموقع.
يعتمد على long polling على تيليجرام وطلبات HTTP (httpx) لـ OpenHands Cloud API (V1).

## الميزات (النسخة الأولى)

- **شاتاتي:** آخر الشاتات بالعنوان والمستودع والحالة وآخر تحديث.
- **فتح شات:** عرض آخر رد أو التقرير النهائي، مع أزرار «رد» و«تحديث» و«رجوع».
- **إرسال برومت:** رد فوري «وصل ✅» في أقل من ثانية، والإرسال الفعلي في الخلفية مع تشغيل تلقائي للـ sandbox الواقف.
- **شات جديد:** اختيار مستودع من GitHub وبدء شات، ومتابعة مهمة البدء لحد READY.
- **إشعار الانتهاء (للمتابَعات):** المراقب يسأل كل 20–30 ثانية في طلب واحد لكل الشاتات المتابَعة، ويبعت التقرير لما تخلص.
- **الإشعارات الاستباقية (عامة):** مُبلّغ منفصل بيراقب **كل** المحادثات وبيلبّغك لما أي واحدة توصل لحالة نهائية — لحد ما توقفها.
- **تقسيم الرسايل الطويلة** عند 4096 حرف، وملف `.md` لو زادت عن 3 أجزاء.

> **مؤجّل مؤقتًا (القرار 4):** الملفات، والتصدير، والتكلفة، وإدارة المتابعات اليدوية
> (قايمة «متابعاتي» وزر تابع/إلغاء) مخفية عن المستخدم حاليًا. الكود والبيانات لسه
> موجودين، والمتابعة التلقائية بعد البرومت بتفضل شغالة.

## الإشعارات

فيه نوعان من الإشعارات، بيتحكموا بشكل مختلف:

| النوع | إمتى بيوصل | إزاي يتحكّم |
| --- | --- | --- |
| **متابَعة صراحةً** | لما محادثة إنت اخترت تتابعها (مثلاً بعد إرسال برومت) توصل لحالة نهائية | بتبان دايمًا؛ مش بتتأثر بمفتاح الإشعارات العام |
| **استباقية (عامة)** | لما أي محادثة تانية توصل لحالة نهائية | تتوقّف/تشتغل من زر «الإشعارات» أو أمر `/notifications` |

- **الإيقاف** بيوقف الإشعارات الاستباقية العامة بس — أوامر البوت وأزراره والمتابَعات الصريحة زي ما هي.
- الحالات النهائية اللي بتنبّه: `finished`، `error`، `stuck`، `waiting_for_confirmation`، و`sandbox_error`
  (خطأ بيئة التنفيذ، مشتق من `sandbox_status` = `ERROR`/`MISSING`).
- التفضيل متخزّن في قاعدة البيانات (جدول `settings`) وبيفضل بعد إعادة التشغيل. الافتراضي **مفعّل**.
- **التعافي:** تسليم إشعار اتقبل من تيليجرام لكن تسجيله فشل بيتعلّم كـ«تسليم معلّق» دائم،
  والدورة الجاية (أو إعادة التشغيل) تكمّل التسجيل **قبل** أي إرسال جديد عشان مايحصلش ازدواج.
- **مفيش ضمان «تسليم مرة واحدة بالظبط»:** لو العملية اتقطعت بين ما تيليجرام يقبل الرسالة وما
  تتكتب علامة التسليم المعلّق على القرص، ممكن الرسالة تتبعت تاني بعد إعادة التشغيل (نافذة معروفة).
- افتراض **عملية واحدة** بتشارك اتصال SQLite واحد؛ مفيش حماية بين عمليات متعددة.

## الإعداد المحلي

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env   # واملأ القيم
python main.py
```

متغيرات البيئة المطلوبة:

| المتغير | الوصف |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من @BotFather |
| `OPENHANDS_API_KEY` | من Settings → API Keys → Create API Key |
| `ALLOWED_TELEGRAM_ID` | الـ ID الرقمي بتاعك (مستخدم واحد بس — القرار 5). البوت يرد عليك أنت بس، وإشعارات المراقب تروحلك |
| `OPENHANDS_BASE_URL` | اختياري، الافتراضي `https://app.all-hands.dev` |
| `WATCHER_INTERVAL` | اختياري، فترة الاستطلاع بالثواني بين 5 و3600، الافتراضي `25` |
| `LOG_LEVEL` | اختياري، واحد من `DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`، الافتراضي `INFO` |
| `DB_PATH` | اختياري، مسار قاعدة SQLite، الافتراضي `bot_state.sqlite3` |

## الاختبار

```bash
pip install -r requirements-dev.txt
python -m pyflakes bot/ main.py tests/   # فحص ثابت
python -m pytest -q                      # كل الاختبارات
```

بوابة الانحدار الكاملة (فحص ثابت + اختبارات) في `docs/REGRESSION_GATE.md`، وبتشتغل تلقائيًا في CI.

CI (`.github/workflows/`) بيشتغل على `push`/`pull_request` على `main` بـ Python **3.11** و**3.13**
(مصفوفة)، وبيشغّل نفس الأمرين: `python -m pyflakes bot/ main.py tests/` و`python -m pytest -q`.

## الأمان

- الأسرار متغيرات بيئة بس، ومش في الكود ولا في GitHub.
- كل رسالة من Telegram ID غير مالِك البوت تتجاهل بصمت.
- أول إجابة من الـ API: 401 بيتحوّل لرسالة «المفتاح غلط»، 410 «الشات اتمسح».
