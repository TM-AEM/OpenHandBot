# OpenHandBot

بوت تيليجرام للتحكم في شاتات OpenHands Cloud من موبايلك بسرعة، من غير ما تفتح الموقع.
يعتمد على long polling على تيليجرام وطلبات HTTP (httpx) لـ OpenHands Cloud API (V1).

## الميزات (النسخة الأولى)

- **شاتاتي:** آخر الشاتات بالعنوان والمستودع والحالة وآخر تحديث.
- **فتح شات:** عرض آخر رد أو التقرير النهائي، مع أزرار «رد» و«تحديث» و«رجوع».
- **إرسال برومت:** رد فوري «وصل ✅» في أقل من ثانية، والإرسال الفعلي في الخلفية مع تشغيل تلقائي للـ sandbox الواقف.
- **شات جديد:** اختيار مستودع من GitHub وبدء شات، ومتابعة مهمة البدء لحد READY.
- **حذف شات (محلي):** من البوت (زر «🗑 حذف الشات» ⇒ تأكيد) ومن الـ Mini App (زر الحذف ⇒ تأكيد/إلغاء). حذف محلي آمن بتأكيد صريح — بيشيل المتابعة/الصندوق/الإكمال/الإشعارات ويسجّل شاهد حذف دائم يمنع إحياء الشات من أي عمل متأخّر؛ **مش** بيمسح الشات من OpenHands نفسه.
- **إشعار الانتهاء (للمتابَعات):** المراقب يسأل كل 20–30 ثانية في طلب واحد لكل الشاتات المتابَعة، ويبعت التقرير لما تخلص.
- **الإشعارات الاستباقية (عامة):** مُبلّغ منفصل بيراقب **كل** المحادثات وبيلبّغك لما أي واحدة توصل لحالة نهائية — لحد ما توقفها.
- **تقسيم الرسايل الطويلة** عند 4096 حرف، وملف `.md` لو زادت عن 3 أجزاء.
- **قائمة أوامر وأزرار جاهزة (OHB2-03):** قائمة أوامر عربية بتتسجّل في واجهة تيليجرام عند التشغيل، أمر `/help`، وأمر/زر `/app` لفتح الـ Mini App لما `MINI_APP_URL` مضبوط.
- **Mini App (OHB2-05/06):** واجهة ويب من جوه تيليجرام على نفس أصل الـ API، بتعمل نفس قدرات البوت: عرض الشاتات، تفاصيل شات + آخر برومت/رد، إرسال برومت، شات جديد، والإشعارات. كل الطلبات بتنادي نفس الخدمات/قاعدة البيانات بتاعة البوت (مفيش منطق مكرّر)، مع مصادقة initData، تحديد معدّل، وحماية Origin. التفاصيل في `docs/MINI_APP.md`.

> **مُفعّلة (F-08 — استرجاع الميزات، القرار A):** الملفات، والتصدير، والتكلفة، وإدارة المتابعات
> اليدوية (قايمة «متابعاتي» وزر تابع/إلغاء) بقيت ظاهرة للمستخدم بعد اعتماد الاسترجاع (2026-11-01).
> الكود والبيانات موجودين، والمتابعة التلقائية بعد البرومت شغالة برضه. المفتاح الواحد
> (`DEFERRED_FEATURES_HIDDEN=True`) بيخفي **أزرار/معالِجات البوت** وواجهة المتابعات في الـ Mini App
> (`watches`/`watch`)؛ لكن مسارات الملفات والتكلفة في الـ Mini App بتفضل متاحة ومحمية بالمصادقة
> والتصريح (fail-closed) — يعني الإخفاء بمفتاح واحد **مش** بيمنع الوصول ليها من الـ Mini App.

## الإشعارات

فيه نوعان من الإشعارات، بيتحكموا بشكل مختلف:

| النوع | إمتى بيوصل | إزاي يتحكّم |
| --- | --- | --- |
| **متابَعة صراحةً** | لما محادثة إنت اخترت تتابعها (مثلاً بعد إرسال برومت) توصل لحالة نهائية | بتبان دايمًا؛ مش بتتأثر بمفتاح الإشعارات العام |
| **استباقية (عامة)** | لما أي محادثة تانية توصل لحالة نهائية | تتوقّف/تشتغل من زر «الإشعارات» أو أمر `/notifications` |

- **الإيقاف** بيوقف الإشعارات الاستباقية العامة بس — أوامر البوت وأزراره والمتابَعات الصريحة زي ما هي.
- الحالات النهائية اللي بتنبّه: `finished`، `error`، `stuck`، `waiting_for_confirmation`، و`sandbox_error`
  (خطأ بيئة التنفيذ، مشتق من `sandbox_status` = `ERROR`/`MISSING`).
- التفضيل متخزّن في قاعدة البيانات (جدول `settings`) وبيفضل بعد إعادة التشغيل. الافتراضي **مفعّل**.
- **التعافي:** تسليم إشعار اتقبل من تيليجرام لكن تسجيله فشل بيتعلّم كـ«تسليم معلّق» دائم،
  والدورة الجاية (أو إعادة التشغيل) تكمّل التسجيل **قبل** أي إرسال جديد عشان مايحصلش ازدواج.
- **مفيش ضمان «تسليم مرة واحدة بالظبط»:** لو العملية اتقطعت بين ما تيليجرام يقبل الرسالة وما
  تتكتب علامة التسليم المعلّق على القرص، ممكن الرسالة تتبعت تاني بعد إعادة التشغيل (نافذة معروفة).
- افتراض **عملية واحدة** بتشارك اتصال SQLite واحد؛ مفيش حماية بين عمليات متعددة.

المرجع الشامل لمنظومة الإشعارات (البنية، القاعدة، الموثوقية، عقد الـ API، الواجهة، التشغيل) في `docs/NOTIFICATIONS.md`.

## الإعداد المحلي

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env   # واملأ القيم
python main.py
```

متغيرات البيئة المطلوبة:

| المتغير | الوصف |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من @BotFather |
| `OPENHANDS_API_KEY` | من Settings → API Keys → Create API Key |
| `ALLOWED_TELEGRAM_ID` | الـ ID الرقمي بتاعك (مستخدم واحد بس — القرار 5). البوت يرد عليك أنت بس، وإشعارات المراقب تروحلك |
| `OPENHANDS_BASE_URL` | اختياري، الافتراضي `https://app.all-hands.dev` |
| `WATCHER_INTERVAL` | اختياري، فترة الاستطلاع بالثواني بين 5 و3600، الافتراضي `25` |
| `LOG_LEVEL` | اختياري، واحد من `DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`، الافتراضي `INFO` |
| `DB_PATH` | اختياري، مسار قاعدة SQLite، الافتراضي `bot_state.sqlite3` |
| `MINI_APP_URL` | اختياري، رابط الـ Mini App العام (https). فاضي = الميزة متوقفة |
| `MINI_APP_ENABLED` | اختياري، `1` لتشغيل خلفية الـ Mini App (ASGI) جوه نفس عملية البوت. الافتراضي `0` |
| `MINI_APP_PORT` | اختياري، منفذ استماع السيرفر جوه الحاوية، الافتراضي `12000` |
| `MINI_APP_INITDATA_MAX_AGE` | اختياري، أقصى عمر لبيانات تهيئة تيليجرام بالثواني، الافتراضي `300` |
| `MINI_APP_SESSION_TTL` | اختياري، عمر جلسة الـ Mini App بالثواني، الافتراضي `3600` |
| `MINI_APP_COOKIE_SECURE` | اختياري، `1` (افتراضي) لكوكي Secure؛ `0` للتطوير المحلي على http فقط |
| `MINI_APP_ALLOWED_ORIGINS` | اختياري، أصول مسموح بيها لطلبات تغيّر الحالة (فواصل). فاضية = بتتشتق من `MINI_APP_URL` |
| `MINI_APP_AUTH_RATE_PER_MINUTE` | اختياري، حد محاولات `/auth` لكل IP في الدقيقة، الافتراضي `10` |
| `MINI_APP_AUTH_RATE_PER_HOUR` | اختياري، حد محاولات `/auth` لكل IP في الساعة، الافتراضي `30` |
| `MINI_APP_API_RATE_PER_MINUTE` | اختياري، حد طلبات الـ API لكل جلسة في الدقيقة، الافتراضي `60` |
| `MINI_APP_RATE_MAX_KEYS` | اختياري، أقصى عدد مفاتيح محدّد المعدّل (حد الذاكرة)، الافتراضي `4096` |

## الاختبار

```bash
pip install -r requirements-dev.txt
python -m pyflakes bot/ main.py tests/   # فحص ثابت
python -m pytest -q                      # كل الاختبارات
```

بوابة الانحدار الكاملة (فحص ثابت + اختبارات) في `docs/REGRESSION_GATE.md`، وبتشتغل تلقائيًا في CI.

CI (`.github/workflows/`) بيشتغل على `push`/`pull_request` على `main` بـ Python **3.11** و**3.13**
(مصفوفة)، وبيشغّل نفس الأمرين: `python -m pyflakes bot/ main.py tests/` و`python -m pytest -q`.

## التشغيل والصيانة

دليل التشغيل الكامل (الإعداد، قاعدة البيانات، التعافي، استكشاف الأعطال) في `docs/OPERATIONS_RUNBOOK.md`.

### سياسة التحديثات المعلّقة (OHB2-02)

البوت بيشتغل بـ `run_polling(drop_pending_updates=True)`: بعد أي إعادة تشغيل أو انقطاع،
التحديثات القديمة المتراكمة **بتترمي** ومش بتتنفّذ. يعني أي أوامر أو رسائل اتبعتت وقت
البوت واقف **مش هتتعالج** — وده **مقصود** للاستخدام الفردي (بيحمي من طوفان أوامر قديمة
ومن تكرار الأوامر بعد إعادة التشغيل). تغيير السياسة دي يتطلب اختبارات لمعالجة التحديثات
القديمة ومنع التكرار.

## الأمان

- الأسرار متغيرات بيئة بس، ومش في الكود ولا في GitHub.
- كل رسالة من Telegram ID غير مالِك البوت تتجاهل بصمت.
- أول إجابة من الـ API: 401 بيتحوّل لرسالة «المفتاح غلط»، 410 «الشات اتمسح».
