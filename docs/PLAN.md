# خطة بوت تيليجرام للتحكم في OpenHands Cloud

تاريخ الخطة: 2026-10-11

> ملاحظة للـ agent المنفّذ: الملف ده هو الخطة الكاملة. لو لقيت أي تعارض بينه وبين الـ API الفعلي، أوقف واسأل صاحب المشروع قبل ما تكمل.

## الهدف والنطاق

البوت بيخليك تتحكم في شاتات OpenHands Cloud من تيليجرام بسرعة، من غير ما تستنى الموقع يحمّل المحادثة كاملة على نتّك البطيء.

- **المشكلة:** الموقع (app.all-hands.dev/canvas) بيحمّل المحادثة بالكامل قبل ما تكمل شغل.
- **الحل:** بوت على سيرفر نتّه سريع بيكلم الـ API الرسمي، ويبعتلك نص صغير بس على تيليجرام.

**نطاق النسخة الأولى:**

1. قايمة الشاتات: العنوان، المستودع، الحالة، آخر تحديث.
2. فتح شات وعرض آخر رد أو التقرير النهائي.
3. إرسال برومت أو رد على شات موجود.
4. شات جديد على مستودع من GitHub.
5. إشعار تلقائي لما الشغل يخلص.

## القرارات المتفق عليها

القرارات دي اتحسمت في النقاش، وما عدا لغة البوت وعدد المستخدمين (افتراضين) كلها مؤكدة.

| البند | القرار |
| --- | --- |
| الاستضافة | Katabump (مجاني، Python أو Node.js) |
| استقبال الأوامر | long polling على عملية شغالة دايماً، بدون webhook |
| تأخير إرسال البرومت | غير مقبول: رد "وصل" في أقل من ثانية، والإرسال لـ OpenHands في الخلفية |
| تأخير إشعار الانتهاء | مقبول لحد دقيقة؛ المقترح polling كل 20 إلى 30 ثانية |
| لغة البوت | عربي (افتراض، محتاج تأكيد) |
| المستخدمين | مستخدم واحد، هو المالك (افتراض) |
| مؤجل | الإيقاف المؤقت، التثبيت، الأرشفة، الحذف، المجلدات |

## الأسرار والمتطلبات

البوت محتاج 3 أسرار بس، وكلها متغيرات بيئة على Katabump.

| المتغير | المصدر | الغرض |
| --- | --- | --- |
| TELEGRAM_BOT_TOKEN | @BotFather ثم /newbot | تشغيل البوت |
| OPENHANDS_API_KEY | app.all-hands.dev/settings/api-keys ثم Create API Key (بيظهر مرة واحدة) | صلاحية البوت على حسابك |
| ALLOWED_TELEGRAM_ID | الـ ID الرقمي بتاعك على تيليجرام | البوت يرد عليك أنت بس |
| OPENHANDS_BASE_URL (اختياري) | الافتراضي https://app.all-hands.dev | الدومين ظاهر في الوثائق بنسختين (all-hands.dev وopenhands.dev) |

**الفرق عن مفتاح الـ LLM:** مفتاح الـ LLM مش مطلوب، لأن الشاتات بتشتغل بالـ LLM المتظبط في الحساب. صفحة API Keys بتعرض مفتاح الـ LLM ومفتاح الـ API جنب بعض، والبوت محتاج المفتاح اللي بتعمله بزر Create API Key (مفتاح اسمه OpenHandBot اتعمل بالفعل).

المفتاح والتوكن يتحطوا في متغيرات بيئة Katabump بس، وما يتبعتوش في أي شات.

## المعمارية

البوت وسيط خفيف على سيرفر سريع: بيستقبل أوامرك فوراً ويكلم OpenHands بالنيابة عنك.

```text
تيليجرام (جهازك)  <---->  [ البوت على Katabump ]  <---- REST V1 ---->  OpenHands Cloud
 أوامرك وردود البوت        |                                           app.all-hands.dev/api/v1
                           |-- استقبال الأوامر: long polling على تيليجرام
                           |-- عميل OpenHands: بيكلم الـ API الرسمي (V1)
                           '-- المراقب (Watcher): polling كل 20 إلى 30 ثانية
                                + SQLite لحفظ الشاتات المتابَعة
                                |
تيليجرام  <---- إشعار الانتهاء --'
```

الأوامر بتوصل البوت فوراً بالـ long polling، والمراقب بيسأل OpenHands عن حالة الشاتات المتابَعة كل 20 إلى 30 ثانية ويبعتلك إشعار الانتهاء.

**هيكل الملفات المقترح:**

- `main.py`: تشغيل البوت والمراقب.
- `handlers.py`: أوامر تيليجرام وأزرارها.
- `openhands_client.py`: كل طلبات الـ API.
- `watcher.py`: متابعة الحالة والإشعارات.
- `db.py`: جداول SQLite.
- `requirements.txt`: الحزم.

## مرجع الـ API المؤكد

كل اللي البوت محتاجه في النسخة الأولى موجود في الـ API الرسمي (V1)، والمسارات دي كلها تحت `https://app.all-hands.dev`.

| الغرض | الطلب | التفاصيل |
| --- | --- | --- |
| شات جديد | POST /api/v1/app-conversations | الجسم: initial_message.content = [{type: text, text}] و selected_repository (و selected_branch اختياري). بيرجّع start task فيه id وstatus. |
| متابعة بدء الشات | GET /api/v1/app-conversations/start-tasks?ids=TASK_ID | استنى status = READY وخد app_conversation_id. ERROR معناها فشل البدء. |
| قايمة الشاتات | GET /api/v1/app-conversations/search?limit=20 | كل عنصر فيه title وselected_repository وsandbox_status وexecution_status وupdated_at. الصفحات بـ next_page_id. الترتيب الافتراضي مش موثق: يتختبر. |
| حالة شات أو أكتر | GET /api/v1/app-conversations?ids=ID | تقدر تبعت أكتر من id في طلب واحد. execution_status: idle, running, paused, waiting_for_confirmation, finished, error, stuck. |
| آخر رد | GET /api/v1/conversation/{id}/events/search?sort_order=TIMESTAMP_DESC&limit=20 | kind__eq بيقبل نوع واحد بس. التقرير النهائي غالباً في ActionEvent بـ FinishAction (الحقل message)، والردود العادية MessageEvent بـ source = agent. البوت يجيب آخر 20 ويفلتر بنفسه. |
| إرسال برومت | POST /api/v1/app-conversations/{id}/send-message | الجسم: role = user، content = [{type: text, text}]، run = true. يشترط sandbox_status = RUNNING. أخطاء: 409 لو الـ sandbox واقف أو بيبدأ، 410 لو الشات مؤرشف، 503 لو فيه خطأ. |
| تشغيل sandbox واقف | POST /api/v1/sandboxes/{sandbox_id}/resume | استنى sandbox_status = RUNNING قبل الإرسال. الـ sandbox_id موجود في بيانات الشات. |
| رسالة قبل ما الشات يجهز | POST /api/v1/conversations/{id}/pending-messages | بتتخزن وتتسلّم لما الشات يبقى READY. الحد 10 رسايل. للشات الجديد بس. |
| مستودعات GitHub | GET /api/v1/git/repositories/search?provider=github&limit=100 | العناصر فيها full_name وmain_branch. query اختياري للبحث وsort_order زي updated-desc. |

**المصادقة:** الوثائق بتذكر 3 أشكال header مختلفة: Authorization: Bearer (دليل Cloud API)، وX-Access-Token (مواصفات OpenAPI)، وX-Session-API-Key (أمثلة الكوك بوك). المرحلة 0 تحدد اللي بيشتغل فعلاً.

## سلوك البوت

كل ميزة في النسخة الأولى ليها شاشة وأزرار محددة، وكل الرسايل بالعربي.

- **/start:** رسالة ترحيب وزرين: "شاتاتي" و"شات جديد".
- **قايمة الشاتات:** آخر 10 شاتات، كل شات زر باسمه وحالته (منتهي، شغال، خامل، موقوف، خطأ، مستني تأكيد). زر "المزيد" بيجيب الصفحة اللي بعدها.
- **فتح شات:** العنوان والمستودع والحالة، وتحتهم آخر رد أو التقرير النهائي، وأزرار "رد" و"تحديث" و"رجوع".
- **إرسال برومت:** زر "رد" بيخلي الرسالة اللي بعده تتبعت لنفس الشات (الاختيار ده لسه مفتوح للنقاش: بديله إن الشات المفتوح يستقبل أي رسالة تكتبها). البوت يرد فوراً "وصل" في أقل من ثانية، وبعدين يكمل في الخلفية:
    1. يشوف sandbox_status. لو RUNNING يبعت send-message.
    2. لو PAUSED يعمل resume ويفحص كل 3 ثواني (حد أقصى دقيقتين) لحد ما يبقى RUNNING، وبعدين يبعت.
    3. لو نجح يغيّر الرسالة لـ "اتبعت" ويضيف الشات للمتابعة. لو فشل يبلغك بالسبب.
- **شات جديد:** زر "شات جديد" بيعرض مستودعاتك (8 في الصفحة، وتقدر تكتب اسم للبحث). بعد ما تختار، ابعت البرومت، والبوت يعمل POST app-conversations ويتابع start task لحد READY ويضيف الشات للمتابعة.
- **إشعار الانتهاء:** كل 20 إلى 30 ثانية البوت بيسأل عن حالة كل الشاتات المتابَعة في طلب واحد. لما حالة شات تبقى finished أو error أو stuck أو waiting_for_confirmation، بيجيب آخر رد ويبعته: سطر فيه العنوان والحالة وتحته النص، وبعدين يشيل الشات من المتابعة. لو الحالة waiting_for_confirmation يقولك تفتح الموقع (التأكيد من البوت مؤجل).
- **الرسايل الطويلة:** تتقسم عند حد تيليجرام (4096 حرف). لو زادت عن 3 أجزاء تتبعت كملف .md.
- **التنسيق:** نص عادي أو HTML مع escape. ما تستخدمش MarkdownV2، لأن أي رمز ناقص بيكسر الرسالة.
- **الأخطاء:** كل خطأ من الـ API يتحول لجملة عربي قصيرة (مثلاً 401: المفتاح غلط، 410: الشات اتمسح الـ sandbox بتاعه).

## التشغيل على Katabump

Katabump المجاني كفاية للبوت ده، بشرط تجديد السيرفر كل 4 أيام.

- **الموارد المجانية:** 308 MB رام و716 MB تخزين و25% CPU، من غير كارت بنكي، لبايثون أو Node.js ([الوثائق](https://docs.katabump.com/getting-started/what-is-katabump.html)).
- **التجديد:** السيرفر المجاني بيتجدد كل 4 أيام، ولو اتنسى البوت بيقف. حط تذكير متكرر كل 3 أيام.
- **النوع:** الاستضافة موجهة لبوتات ديسكورد، لكن فيه أدلة منشورة لتشغيل بوتات تيليجرام عليها.
- **الإعداد:** إنشاء سيرفر Python (ملفات requirements.txt وmain.py)، رفع الملفات بـ ZIP أو SFTP، ضبط متغيرات البيئة، Start. الحزم بتتثبت تلقائياً أول تشغيل.
- **التقنية المقترحة:** Python مع aiogram وhttpx وSQLite، وبديلها Node.js مع grammY. الاتنين خفاف تحت 308 MB.
- **الاستقبال:** long polling بس، علشان مفيش حاجة تحتاج منفذ وارد.
- **التخزين:** ملف SQLite فيه الشاتات المتابَعة وآخر حالة لكل واحد، وحالة الحوار (مستني برومت لأنهي شات). لو الملف اتمسح البوت يبدأ من الأول من غير خسارة، لأن الشاتات نفسها على OpenHands.
- **السجلات:** من لوحة Katabump مباشرة، وما يتطبعش فيها المفتاح ولا التوكن.
- **خطة بديلة:** لو Katabump وقف أو اتقيّد، نفس الكود يشتغل على أي VPS أو منصة تانية من غير تعديل.

## المراحل وقوائم الفحص

التنفيذ على 4 مراحل، وكل مرحلة بوابتها لازم تعدي قبل اللي بعدها.

### المرحلة 0: اختبار الـ API (حوالي 15 دقيقة، قبل أي كود بوت)

بالمفتاح كمتغير بيئة، شغّل طلبات curl وسجّل النتايج:

- [ ] أي header للمصادقة بيشتغل (Bearer أو X-Access-Token أو X-Session-API-Key).
- [ ] قايمة الشاتات بترجّع نفس الشاتات اللي في الموقع (زي الشاتات المثبتة)، ومعرفة الترتيب الافتراضي.
- [ ] events/search على شات منتهي: فين التقرير النهائي بالظبط (FinishAction ولا MessageEvent).
- [ ] send-message على شات تجريبي، وسلوك الـ sandbox الواقف (409 ثم resume).
- [ ] repositories/search بـ provider=github بترجّع مستودعاتك.
- [ ] هل POST app-conversations بيقبل بدون selected_repository.

**البوابة:** لو أي نقطة فشلت، الخطة تتعدل قبل المرحلة 1.

### المرحلة 1: الأساس

- [ ] allowlist بالـ Telegram ID، وأي حد تاني يتتجاهل.
- [ ] قايمة الشاتات وفتح شات وعرض آخر رد.
- [ ] إرسال برومت مع رد "وصل" الفوري، وresume تلقائي للـ sandbox الواقف.
- [ ] تقسيم الرسايل الطويلة.

**البوابة:** برومت من تيليجرام يوصل بعد أقل من ثانية، ويظهر في الموقع.

### المرحلة 2: شات جديد والإشعارات

- [ ] قايمة المستودعات مع البحث، وبدء شات جديد.
- [ ] المراقب وإشعار الانتهاء مع التقرير.
- [ ] جدول SQLite للشاتات المتابَعة.

**البوابة:** شات جديد من البوت بيخلص وتوصلك رسالة التقرير في أقل من دقيقة بعد الانتهاء.

### المرحلة 3: التثبيت على Katabump

- [ ] رسايل أخطاء عربي واضحة وإعادة محاولة عند فشل الشبكة.
- [ ] ملف .md للتقارير الطويلة.
- [ ] رفع على Katabump وتشغيل أسبوع متواصل، مع تذكير التجديد.

## الأمان

تسريب توكن البوت أو مفتاح الـ API معناه تحكم كامل في حسابك، لأن OpenHands ينفّذ كود ويرفع على GitHub.

- **allowlist:** أي رسالة من Telegram ID غير ID المالك تتجاهل بصمت، من غير أي رد.
- **الأسرار:** متغيرات بيئة بس. مش في الكود، ومش في GitHub، ومش في أي شات.
- **التسريب:** لو المفتاح اتسرب، احذفه من Settings ثم API Keys وأنشئ واحد جديد، وغيّر توكن البوت من BotFather.
- **السجلات:** ما تطبعش المفتاح ولا التوكن ولا نص البرومتات كامل.
- **التشفير:** شاتات البوتات على تيليجرام مش مشفرة طرف لطرف، فما تطلبش من الـ agent يعرض أسرار في تقاريره.
- **الصلاحيات:** النسخة الأولى مفيهاش أوامر حذف ولا تغيير إعدادات.

## المخاطر والافتراضات والمؤجل

أكبر خطرين: الـ API بيتغير بسرعة، ونسيان تجديد Katabump كل 4 أيام.

| الخطر | الأثر | التعامل |
| --- | --- | --- |
| الـ API بيتغير (الإصدار القديم V0 اتشال، ودومينين) | البوت يتكسر | العنوان إعداد، والمرحلة 0، ورسايل أخطاء واضحة |
| شكل التقرير النهائي مش زي المتوقع | يتعرض آخر رد غلط | اختبار المرحلة 0، وبديل: آخر MessageEvent من الـ agent |
| نسيان تجديد Katabump | البوت يقف | تذكير كل 3 أيام، وخطة بديلة |
| حد الشاتات المتزامنة (الأقدم بيتوقف) | شات يبقى موقوف | البوت يعرض "موقوف" ويعمل resume قبل الإرسال |
| الـ sandbox واقف أو مؤرشف (409 أو 410) | الإرسال يفشل | resume لـ 409، ورسالة واضحة لـ 410 |
| الشات في waiting_for_confirmation | الشغل واقف | البوت يبلغك تفتح الموقع |
| حد تيليجرام 4096 حرف | تقرير مقطوع | تقسيم الرسايل وملف .md |

**افتراضات محتاجة تأكيد:**

- لغة البوت عربي.
- مستخدم واحد، هو المالك.
- المفتاح بيشوف نفس شاتات الموقع (بتتأكد في المرحلة 0).

**مؤجل لبعد النسخة الأولى:**

- الإيقاف المؤقت: فيه pause على الـ agent-server وpause للـ sandbox كله، ولازم نعرف زر الموقع بيعمل أنهي واحد.
- التثبيت والمجلدات: مفيش لهم حقل في الـ API.
- الأرشفة: في الموقع محفوظة في المتصفح مش على السيرفر، فالحل أرشفة داخل البوت نفسه.
- الحذف: DELETE /api/v1/app-conversations/{id}، مع تأكيد.
- الموافقة على إجراءات الـ agent من البوت.
- تلخيص التقارير الطويلة بالـ LLM.

## برومت للـ agent المنفّذ

انسخ البرومت ده كما هو للـ agent اللي هينفّذ، وادّيله الملف ده معاه.

```text
عايزك تنفّذ بوت تيليجرام يتحكم في شاتات OpenHands Cloud، حسب خطة الملف المرفق.

قواعد:
1. ابدأ بالمرحلة 0 (اختبار الـ API بـ curl) ولا تكتب كود البوت قبل ما تنتهي منها. اعرض عليّ نتايجها.
2. المفتاح ومتغيرات البيئة: TELEGRAM_BOT_TOKEN وOPENHANDS_API_KEY وALLOWED_TELEGRAM_ID وOPENHANDS_BASE_URL. ما تكتبهمش في الكود ولا في GitHub.
3. الاستقبال بـ long polling، والبوت يرد على ALLOWED_TELEGRAM_ID بس.
4. إرسال البرومت لازم يرد "وصل" في أقل من ثانية، والإرسال الفعلي في الخلفية مع resume تلقائي للـ sandbox.
5. إشعار الانتهاء بـ polling كل 20 إلى 30 ثانية، في طلب واحد لكل الشاتات المتابَعة.
6. الرسايل بالعربي، وتقسيم أي رسالة فوق 4096 حرف.
7. النطاق: النسخة الأولى فقط. الإيقاف والتثبيت والأرشفة والحذف مؤجلة.
8. التشغيل على Katabump (Python، 308 MB رام). حافظ على الحزم خفيفة.
9. لو لقيت أي تعارض بين الخطة والـ API الفعلي، أوقف واسألني قبل ما تكمل.
```
