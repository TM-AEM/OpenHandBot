## 2. Critical Cross-Feature Interaction Notes

1. **Default Feature Flag Mismatch (`DEF-001` × `DEF-015`):** Stage B remote attachment delivery is `Deferred` (`BLOCKED`), yet Stage A local attachment intake (`ATTACHMENT_DOCUMENT_INTAKE_ENABLED`) defaults to `True` (`Enabled`). Because Stage A3 (`UNRESOLVED` `intent_recorded`) and D-34 (`TERMINAL_UNPROVEN`) block all future text messages globally per user, leaving Stage A enabled without Stage B or a batch-clear escape hatch breaks normal text prompting after one attachment upload.
2. **Polling Deadlock Amplification (`DEF-002` × `DEF-005` × `DEF-010`):** Missing poison-update quarantine (`Missing`) turns every unhandled exception — including the 24 unwrapped stale `q.answer()` sites (`DEF-005`), unwrapped `send_document` `TimedOut` (`DEF-004`), and 64-byte `callback_data` crashes (`DEF-010`) — into an infinite Telegram polling freeze.
3. **Mini App Boundary Separation (`EXCLUDED_MINI_APP`):** Disabling `ATTACHMENT_DOCUMENT_INTAKE_ENABLED` by default in `bot/config.py` affects only Telegram document intake (`bot/handlers.py`) and leaves all Mini App code (`bot/web/*`, `bot/web/static/*`) completely untouched. However, `OHB2-MT-2` attachment download inside the excluded Mini App depends on bot-side staged `pending` batches, so turning off intake by default pauses new `MT-2` transfers unless an operator explicitly opts back in *after* `DEF-001` is fixed.
